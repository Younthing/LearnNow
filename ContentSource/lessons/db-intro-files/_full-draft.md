# 完整讲义稿（存档，不编译）

## Brief（写作合同）

| 项 | 内容 |
|----|------|
| **核心问题** | 为什么不能一直用普通文件保存数据？ |
| **心智模型** | 文件解决「放得下」；数据一多、常改、多人同时动时，需要 DBMS 夹在中间按指令查改，而不是整份覆盖。 |
| **学习者起点** | 零数据库术语；知道手机/电脑能存文件即可。 |
| **终点行为** | 1. 能判断场景是「文件够用」还是「该上数据库」。2. 能说出 DBMS 夹在程序与数据之间做什么。 |
| **概念预算** | 核心：文件不够用的临界条件。支撑：整份覆盖风险、按条件改一行、DBMS 中间层。识别：并发。延后：表结构、SQL。 |
| **贯穿例子** | 日日咖会员名单（姓名、电话、积分）。 |
| **范围边界** | 会讲：文件瓶颈、DBMS 角色。不讲：SQL 语法、表设计、具体产品名差异。 |

## 讲义

日日咖用表格记会员，人少时顺手；人一多、天天改积分、两人同时打开，就会互相覆盖。文件擅长存，不擅长在频繁改动与多人协作下保证「改对那一行」。数据库管理系统夹在你和磁盘数据中间：你下指令，它定位、改写、尽量处理冲突。它不替你想业务字段，但替你把脏活从「整份文件覆盖」里抽走。
