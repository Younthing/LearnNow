# 结构化短页骨架

一页 = 一个概念簇 = 1～2 个 objective = **约 3 屏**结构化正文 ＋ 1～2 道题，读完做完
约 3～5 分钟。一个 Lesson 最多 3 页，所以每一页都得撑得起一个完整的小主题——但撑起
主题靠的是**结构**，不是字数。

数量上的锚：**250–450 汉字散文**，2～4 个 `##`，至少 1 个 fenced `text` 块，1 个
`@Callout`，1～2 道 `@Quiz`。写超了就删、画、分、移（见 `references/pedagogy.md`
§ 拆墙的正确动作），**不要**指望"多写几段就讲透了"。

页面文件里**没有** front matter；标题写在 `lesson.yml` 的 `title` 里，正文**不写 `#`**，
分区块从 `##` 开始，最深到 `###`。

## 骨架

```text
[1] 承接（1–2 句，散文）
    —— 让本页读起来像上一页的下一句，不重新自我介绍。第 1 页则用一个能感觉到的问题开场。

[2] 30 秒答案（2–4 句，散文，约 60–90 字）
    —— 直接给本页的最小正确方向。不讲历史、不堆术语、不提前展开例外。
    —— 第一屏陌生术语 ≤3 个。

[3] ## 第一个任务（现象 / 最小例子）
    —— 1～3 段短文 ＋ 一处 fenced text，把序列、对照或层次画出来。
    —— 别用三段散文描述一条流程；那正是该画进块里的东西。

[4] ## 第二个任务（机制：发生了什么）
    —— 因果用短段或编号列表，不用平铺无序列表代替解释。
    —— 每段 2～4 句，只表达一个关系。

[5] ## 第三个任务（命名与边界 / 什么时候用哪个）
    —— 先现象后术语；给一句定义，再给一个适用边界或一个常见误解。
    —— 真正并列的判断依据才用单层列表。

[6] @Callout ×1（最多 2）
    —— 只装一句学习者能脱稿复述的话，不堆术语。

[7] @Quiz ×1–2（不超过 2）
    —— 一道判断/区分，一道迁移。答案不能已被 Callout 或散文原句说完。
```

`##` 的数量就是"这一页做了几件事"。做不满两件事，说明该和相邻页合并；超过四件，说明
该拆成同 Track 的下一个 Lesson。

对比在 `##` 里的正确做法：先各用一句话建立两个对象，再用**短 GFM 表**（建议 ≤4 列）、
单层列表或 fenced `text` 对照格列 3～5 个判断维度。**不写嵌套列表**——那是编译错误。

## 成品示例（对照用；ID 用 `example-` 前缀，不要直接复制到真实 Lesson）

注意它的形状：散文约 330 字，三个 `##`，一处 fenced 块，一处短 GFM 表，一个
`@Callout`；数字用 `` `code` ``，关键判别用 `**bold**`，没有任何一段超过四句。

````markdown
上一页我们用平均分描述了一个班的整体水平。现在把同一个班拿过来，只改一个人的成绩。

一个人的分数从 `60` 改成 `600`，平均分立刻被拉高一大截，中位数几乎没动。这一页只讲这个
差别从哪来，以及什么时候该信哪一个。

## 加起来，还是排排队

先把两个词各建立一次。平均分是把所有分数加起来再除以人数；中位数是把分数从小到大排好，
取站在正中间的那个。

「加起来」让每个分数都有份，「排队」只关心谁站在中间。同一组分数，两种做法给出两个结果：

```text
分数    55   60   62   65   600
平均    加起来 ÷ 5      →  168
中位    取正中间那个    →  62
```

## 为什么排队不怕极端值

把 `600` 再改成 `6000`，队伍的顺序一点没变，正中间站的还是同一个人，中位数还是 `62`。
中位数看的是**位置**。

平均分不一样。`6000` 会完整地进入总和，除完之后每个人都被它抬高了一截。它看的是**数值**。

## 什么时候看哪一个

两个数已经立住了。扫一眼下面这张表，就能在多数日常场景里选对人：

| 场景 | 更信哪个 | 原因 |
| --- | --- | --- |
| 分数集中、无离群 | 哪个都行 | 两个数会很接近 |
| 少数值被拉远 | 中位数 | 更接近「典型的那一个」 |
| 你要的本来就是总量 | 平均值 | 问的就是总和再平均 |

@Callout(title: "位置还是数值", tone: "information", accent: "purple") {
极端值改的是**数值**，不是**位置**。所以它拉得动平均，拉不动中位。
}

@Quiz(id: "example-center.quiz-1", kind: "singleChoice") {
一个小区 20 户人家，其中一户中了大奖。第二天统计"这个小区的收入水平"，哪种说法更站得住？

@Option(id: "example-center-q1-median", correct: true) {
用中位数，因为中奖那户只改变了自己的位置排序，没改变中间那户是谁

@Feedback(title: "位置没变", tone: "success", accent: "mint") {
中奖那户从右边第几名变成右边第一名，正中间的人还是原来那位。
}
}

@Option(id: "example-center-q1-mean") {
用平均数，因为它把所有 20 户都算进去了，信息更完整
}

@Option(id: "example-center-q1-drop") {
把中奖那户删掉再算平均，这样两个数就都准了
}

@Feedback(when: "correct", title: "回答正确", tone: "success", accent: "mint") {
"更完整"和"更有代表性"是两回事：算进去不等于代表得了。
}

@Feedback(when: "incorrect", title: "先问它拉动了什么", tone: "warning", accent: "amber") {
把中奖金额再翻十倍，重新排一次队：正中间那户换人了吗？没换，就说明中位数不受它影响。
}
}

@Quiz(id: "example-center.quiz-2", kind: "singleChoice") {
你在看一个接口的响应时间。平均 200 毫秒，中位数 80 毫秒。按这一页的思路，最可能的情况是？

@Option(id: "example-center-q2-slow-tail", correct: true) {
多数请求很快，有少数请求特别慢，把平均拉了上去
}

@Option(id: "example-center-q2-uniform") {
所有请求都在 80 到 200 毫秒之间均匀分布
}

@Feedback(when: "correct", title: "回答正确", tone: "success", accent: "mint") {
平均明显高于中位，通常意味着右边有几个拖后腿的极端值。
}

@Feedback(when: "incorrect", title: "把两个数摆在一起看", tone: "warning", accent: "amber") {
如果请求真的均匀分布，平均和中位会很接近。它们差了两倍多，差额得有个来源。
}
}
````

## 常见写坏的信号

- **眯起眼睛看，整页是一片均匀的灰** → wall of text，否决项 A12。
- 本页第一句在重新介绍自己（"在本节中我们将学习……"）→ 缺 [1]。
- 读到第二屏还不知道这页要回答什么 → 缺 [2]。
- 连着三段普通段落中间没有任何标题／列表／块 → 断点密度不够，该分块或该画图。
- 某个 `##` 下面压着 150 字以上的连续散文 → 那一段里通常藏着一张没画出来的图。
- 一段超过四句或超过 90 字 → 它同时表达了两个关系，切开。
- 整页没有一处 fenced 块 → 抽象关系全靠散文，双编码缺位。
- ` ```text ` 用空格拼多栏、或一行特别长 → 窄屏会碎行（rubric C12）；改竖排/`├─`/表。
- 单页散文明显超过 450 字 → 先删"顺带一提"和第二个例子；仍放不下就整块移到下一课。
- 一页出现 3 道题 → 超预算，挑最有判断价值的 1～2 道。
- `@Callout` 读起来像术语摘要 → 改写成学习者会说的话。
- 整页灰字、扫一眼抓不住钉子 → 缺 `**bold**` / `` `code` ``（rubric C10）。
- 几乎每个名词都加粗，或散文里一串 `` `词` `` → 强调过密（rubric C11）；每节粗体压到 1～3 处。
- 题目能靠常识猜对，或答案在上一段原句里 → 干扰项没落在真实迷思上，或答案被剧透。
- 拆出了 4 页 → 概念预算爆表，把第 4 页的内容整段做成同 Track 的下一个 Lesson。
