# Pedagogy — LearnNow 教案内核

本文件是 LearnNow 教案的写法依据。它把几家高质量创作者的**可执行内核**，以及一套零基础
写作指南与质量标准，抽出来与认知科学的既有结论合并成 checklist，最终写成 LearnNow 自己
的语言。

它不是文风模板。见文末「禁止表面模仿」。

---

## 一、来源与抽出的内核

| 来源 | 抽出的内核（可执行） | 落到 LearnNow 的动作 |
|------|----------------------|----------------------|
| Real Python | 清晰层级：动机 → 最小例子 → 解释 → 变体/陷阱。散文可读，术语首次出现即落地为具体所指。 | 每页按这个层级排；任何术语第一次出现的同一句里必须给出它指的具体东西。 |
| TestDriven.io | 小步递进，每一步都能被验证。先让学习者拿到一个**能跑通**的心智模型，再去扩边界。 | 页内最后一步一定是学习者能自己验证的动作（一道题、一次心算、一次判别）；不留"以后你就懂了"。 |
| StatQuest | 一次只推一个想法；用极小的数字例子把直觉磨出来；关键结论用友好口吻复述一次。 | 一页一个概念簇；例子里的数字要小到能心算；每个 `##` 区块最多一处"换句话说"的复述。 |
| 3Blue1Brown | 先给"看见本质"的直觉锚点，再给形式名字；用贯穿的数量/空间隐喻让抽象变得可想象。 | 先描述现象与操作，再命名；隐喻在整课内保持同一个，不中途换喻。 |
| CS50 notes | 零基础入口；同一素材多种解释（数字 → 文字 → 颜色）；用好奇问题开场。**只作选题与例子矿，不作唯一文风模板。** | 允许沿用其经典选题路径与"同一对象多解释"的结构，但文案全部原创。 |
| 零基础写作指南 / 质量标准 | 一文一问、一文一模型、写作合同、概念预算、30 秒答案、主线测试、重复须升级、练习闭环。 | 全部内化为下面第二～四节的硬规则；Brief 是它们的入口。 |

## 二、写作合同（Lesson 级）

一个 Lesson 只回答**一个核心问题**，只留下**一条心智模型**。整课的合同在 Brief 里填完
（表格见 `SKILL.md` § 1），其中最容易被跳过、又最能救命的是概念预算：

| 类型 | 预算 |
|------|------|
| 核心概念（读完要能自己解释） | 1 个 |
| 必须掌握的支撑概念 | 2～4 个 |
| 只需识别、不展开 | ≤5 个 |
| 需要正式定义的术语 | ≤4 个 |
| 核心对比 | 0～1 组 |
| 延后到下一课 | 写清楚，正文里最多留一句预告 |

每个新术语出现时，作者要能立刻说出它属于**掌握 / 识别 / 延后**哪一档。预算超了就拆成
**同一个 Track 里的下一个 Lesson**，既不多加一页，也不把某一页写长——页数上限是 3，
每页上限是三屏。**深度靠多一课，不靠多一屏。**

### 主线测试

每一段、每一个区块都要能回答：**这一段是否直接帮助回答本课核心问题？** 只是"间接相关"
时，三条出路：压成一句预告、移到下一课、删掉。写完再做一遍**快速删减测试**：

1. 删掉它，核心问题还答得出来吗？
2. 它是否属于下一课？
3. 它是否只是换一种说法重复？
4. 它是否引入了新术语却不承担核心作用？
5. 它是否让内容更完整，却没有让学习者更会用？

任一为「是」→ 删除、合并或移动。

### 重复必须升级理解

同一个观点第二次出现，必须至少完成一件新任务：加入机制、加入边界、加入反例、用来解释
新现象、或用来完成一次判断。只是换一种说法的重复是注水，评审会打回。

## 三、认知科学 checklist

写完每一页都要能对下面每条回答"是"。

1. **认知负荷**：本页只引入一个概念簇（一个主概念 ＋ 最多一个紧邻从属概念）。旧概念一律
   用**同一个贯穿例子**复用；换场景会凭空增加外在负荷，是缺陷。
2. **第一屏克制**：页面开头 2～4 句内给出该页的最小正确方向，且第一屏出现的陌生术语
   **不超过 3 个**。第一屏之内就要出现第一个 `##`，别让开场自己变成一堵小墙。
3. **具体先于抽象**：先给实例和"这一步在做什么"，再给术语和定义。定义出现在实例之后，
   不在之前。
4. **新知识要有挂接点**：术语出场前，必须已经有一个问题、一段旧经验，或一个"没有它就会
   出错"的现象在等着它。
5. **检索练习**：Quiz 考"会不会用 / 能不能区分"，不考"背不背得出定义"。学习者要在题目里
   做一次真实的判断。
6. **迷思概念定向**：干扰项对应一个真实会犯的错，而不是明显荒谬的选项；`incorrect`
   反馈必须指名那个误解，并给出一步可执行的自检。
7. **双编码**：能用对比、序列、小的关系表达就用；即使本轮不配图，文字也要能在脑内成像
   （"八个开关排成一排"优于"一个八位的向量"）。
8. **生成效应 / 费曼**：`@Callout` 写学习者能用自己的话复述出来的一句，而不是术语堆叠。
   一句读完就忘的漂亮话不算洞见。
9. **合意困难**：题目要略需想一想，但绝不依赖本课未教的知识。停在最近发展区里。
10. **简化不等于省略关系**：可以省历史、实现细节、罕见例外；**不能**省主要因果、适用前提、
    与相近概念的关键边界。写下的每个简化都要能说出它在什么条件下成立。
11. **间隔复习钩子**：Card / Tip 只收易忘的**判别点**，不复述整页散文。

## 四、流程：先完整稿，再拆页

### 为什么这个顺序不能反

直接写微课页会产出一堆互不相识的卡片：每页都对，合起来没有故事。先写连贯讲义，叙事、
例子和口吻在一次连续思考里定型；拆页只是切分，不是重写。

### 完整稿的写法

- **开场**：一个学习者能感觉到的问题，不是定义，也不是"本节我们将学习"。
- **30 秒答案**：前 150 字内给出简化但正确的答案。不讲历史、不堆术语、不提前展开例外。
  只读这一段的人也不应拿到错误模型。
- **贯穿例子**：第一段就出现，之后每一段都用它。挑一个学习者当天就可能碰到的具体对象，
  并且能被反复换角度看，而不是每讲一个概念换一个新场景。
- **一段一步**：每段只把理解推进一步，2～4 句就收。若一段里出现两个"其实"，拆成两段。
- **术语落地**：术语出现处的同一句里给出它指的具体东西。
- **命名顺序**：现象 → 最小例子 → 发生了什么 → 命名 → 正式定义 → 边界与误解。
- **收口**：把全课钉在一句可迁移的判断上，并为后续课留一个具体钩子。

完整稿存为 `_full-draft.md`，只作存档，不进编译。

**完整稿也有预算。**它最终要装进最多 3 页、每页 250–450 汉字，所以散文总量控制在
**约 1000–1300 汉字**。写到两千字再去"拆"，拆出来的一定是三堵墙。草稿写超了，说明
概念预算爆了，该分成两个 Lesson。

### 拆页的规则

- **一个 Lesson 最多 3 页。** 切点在"支撑概念簇开始"处，不在每个新术语处，也不在字数处。
- 每页 1～2 个 `objective`，用行为动词写（"能判断/能解码/能区分"），不用"了解/掌握"。
- 页间口吻与例子必须连续：第 3 页读起来要像第 2 页的下一句话。
- 拆完通读一遍：如果去掉页码后读不出一条故事线，就是拆坏了，回到完整稿改。
- 拆不出 3 个不同的"这一页替学习者解决了什么"，就只用 2 页。
- 拆完发现某页放不下，**不要让它变长**：把溢出的部分做成同 Track 的下一个 Lesson。

### 单页节奏

承接 → 30 秒答案 → 机制（`##` 分块）→ 命名与边界 → 1～2 `@Callout` → 1～2 `@Quiz`。

目标：约 **250–450 汉字**散文 ＋ 结构块，在手机上**约 3 屏**刷完，读完做完约 3～5 分钟。
600–900 汉字的一页不是"讲透了"，是**没删干净**。骨架见 `examples/page-skeleton.md`。

字数不是靠压缩句子省出来的，是靠**少讲一点、多分块一点**省出来的：把两个例子砍成一个，
把三段解释压成一个 fenced 模型图，把"顺带一提"整段移到下一课。

## 五、页内排版规范（硬要求）

页面正文是**结构化短文**，不是一段小字，也不是一篇散文。学习者在手机上竖着刷，屏幕上
出现一大片没有断点的汉字时，他不会读得更认真，只会划走。

### 不许出现的「墙」（否决项）

**wall of text = 页面主体是连续长段落，中间几乎没有结构块。**只要出现下面任一形态，
评审可直接打回：

- 连续 **3 段及以上**普通段落之间没有任何 `##` / 列表 / fenced 块 / `@Callout`；
- 某个 `##` 区块里的散文超过约 **150 汉字**却一个块都没有；
- 出现 **5 句以上**不分段的长段，或一段超过约 **90 汉字**；
- 整页只有 1 个 `##`，或全页没有任何 fenced 块。

### 视觉断点的密度

- 页内用 `##` 分区块，必要时再用 `###`；**不写 `#`**——课页标题在 `lesson.yml` 的 `title`
  里，正文再来一个一级标题是重复。最多用到 `###`。
- **每页 2～4 个 `##`**，每个 `##` 下面的正文控制在 1～3 段。
- 每个 `##` 只承担一个任务，标题本身要说得出这个任务（"编号从 0 开始"优于"补充说明"）。
- 一段 **2～4 句 / 约 60–90 汉字**，只表达一个主要关系；段落之间必须留空行。
- 每屏（约 150 汉字）至少要有一个结构性断点：一个小标题、一个列表、一个 fenced 块或一个
  `@Callout`。
- 模型、序列、对照关系用 fenced ` ```text ` **画出来**：一页至少一处可成像的块。
- 洞见用 `@Callout`，一页 1 个（最多 2 个），每个只装一句可脱稿复述的话。

### 行内强调（硬要求）

页面要有节奏变化，不能整页灰字。行内格式是**稀疏的视觉锚点**，不是装饰：

| 写法 | 用在 | 节制 |
|------|------|------|
| `**bold**` | 本节真正要钉住的 1～3 个关键短语（判别点、对比轴、结论词） | **每 `##` 节最多 1～3 处**；不加整句粗体 |
| `` `inline code` `` | 具体 token：例子里的数字、fenced 模型里的节点标签、短技术名词 | 只标**可指认的具体物**；普通散文名词不加反引号 |
| `*emphasis*` | 轻微语气倾斜（少用） | 一页最多零星几处；不要和粗体抢戏 |

硬否决：

- **bold-every-noun**：几乎每个名词都加粗 → 等于没有强调；
- **backtick soup**：普通叙述里一串 `` `词` `` → 页面变代码注释，不是课；
- 整句或整段包进 `**...**`。

正确感觉：扫一眼能抓住本节的钉子，其余仍是可读的口语散文。

### 用哪种块

- **因果与过程用短段或编号列表**；只有真正并列、同层级的信息才用无序列表。用列表代替
  机制解释是坏味道，反过来用长段落代替一张 fenced 模型图同样是坏味道。
- **对比不用表格。** 编译器没有表格 IR，GFM `|` 表是 hard error。做法：先各用一句话把
  两个对象建立起来，再用单层列表或 ` ```text ` 对照格给出 3～5 个最有判断价值的维度。
- **列表不许嵌套**（编译器 `list.unsupportedNesting`）。需要层级时改成 `###` 分节，或把
  层级画进 fenced 块。
- 引用块 `>`、链接、raw HTML、inline 图片同样是 hard error。要强调就用 `**strong**`、
  `` `code` ``（具体 token）或 `@Callout`——不要退回引用块。

### 拆墙的正确动作

发现一页太密时，按这个顺序处理，**加页数与加字数都不在选项里**：

1. 删——跑一遍快速删减测试，砍掉"顺带一提"和第二个例子；
2. 画——把三段机制解释换成一个 fenced `text` 模型图；
3. 分——给每个新任务一个 `##`，把长段切成 2～4 句的短段；
4. 移——还是放不下，就把剩下的内容做成**同 Track 的下一个 Lesson**。

## 六、语言与句式

- `zh-Hans`。口语、清晰、成年人对成年人说话。
- 不卖萌、不堆网络梗、不用感叹号催情绪；也不用学术腔和"综上所述"。
- 短句优先。一句话里塞两个从句就拆开。
- 中英混排时，英文术语与中文之间自然留白由排版处理，不手动加空格以外的修饰。
- 数字例子必须小且可心算；避免任何需要按计算器的数字。数字一旦作为例子里的**具体值**出场，
  优先写成 `` `60` `` / `` `600` `` 这类 inline code，让读者一眼认出它是 token，不是散文。
- 行内强调见上节「行内强调」：`**bold**` 钉关键短语，`` `code` `` 钉具体 token；二者都要稀。
- 不写"很简单""显然""众所周知"——它们只会让卡住的人更羞耻。
- 绝对化表述改成带条件的表述（"通常""在……的前提下"），并至少写出一个适用边界。
- 不承诺本课不兑现的东西（"后面会讲"最多出现一次，且必须指向真实存在的后续内容）。

### 比喻

- 一个 Lesson 最多一个主要比喻，只承担一个解释任务。不需要就不加。
- 用了就必须写清三件事：对应关系、它只解释什么、它**不能**解释什么，然后回到真实机制
  用术语重说一次。比喻不能替代机制。

## 七、Quiz 写法

- **每页 1～2 道，不超过 2 道。** 整课的练习要覆盖闭环：至少一次回忆（不看正文答）、
  至少一次区分或判断、尽量有一次迁移到稍有变化的新情境。
- 题干是情境，不是填空。让学习者做一次真实判断。
- 2–3 个选项。干扰项来自真实迷思，比如把 bit 与 byte 混用、以为字符"自带"数字。
- 正确反馈解释**为什么对**，让答对的人也学到东西。
- 错误反馈先指名误解，再给一步自检动作。
- 答案不能已经被同页 `@Callout` 或散文原句说完；那样题目退化成句子匹配。
- 不出"以下哪项不属于……"这类靠排除法的题；不出考记忆细节的题（如"ASCII 有多少个码位"）。

## 八、间隔复习：Card 与 Tip

- Card 正面是一个能引发提取的提示词，不是一个问题的完整重述。
- Card 背面：一段简短正文 ＋ 一个 `@Highlight`，`@Highlight` 放最容易忘的判别点。
- 一页最多产出两张 Card；不是每页都必须有 Card。宁少而准。
- Tip 是学习者在首页闲逛时看到的一句话，脱离上下文也要成立。

## 九、禁止表面模仿

上表来源提供的是**结构与决策依据**，不是嗓音。以下都视为缺陷，评审可直接打回：

- 复刻某频道的口头禅、开场白、招牌感叹或人格面具；
- 使用中译的"标志性句式"去模拟某位讲者的语气；
- 把"友好复述"写成撒娇或角色扮演；
- 为了像某家风格而牺牲准确性或加入本课不需要的可爱比喻；
- 假装有视频/动画在旁边（"看这个动画"），LearnNow 是文字微课；
- 把写作指南的章节编号原样抄成页面结构（"## 0. 写作合同""## 1. 30 秒答案"）——那是给
  作者看的脚手架，学习者看到的应该是有内容的小标题。

判据很简单：如果一位读者能说出"这在模仿谁"，就写坏了；如果读者只觉得"讲得清楚"，
就写对了。
